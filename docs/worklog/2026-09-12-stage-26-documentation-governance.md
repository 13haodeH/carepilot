# 阶段二十六工作记录：文档治理、PRD 与 AI 迭代台账

- 记录日期：2026-09-12
- 关联 MVP：MVP1 说明性文档补充；不改变 `carepilot-mvp1` 的代码、运行、实验输入或发布结论
- 关联 Git 提交：本记录与同批文档将在独立提交中保存；用 `git log -- docs/` 定位最终提交

## 1. 问题与假设

MVP1 已具备工作记录、实验报告和发布材料，但缺少统一文档入口、当前 PRD、集中 Prompt 版本台账和坏例总表。作品集案例页也无法让读者判断所谓“Prompt 迭代”是否真实发生、是否是纯 Prompt 效果。

本次假设是：用文档层级、变更台账和明确的版本规则，可以让每次已记录的错误、修复、评测和发布决定更快定位，同时避免为满足 AI PM 作品集模板而编造 Prompt V1→V3 成果。

## 2. 范围和不做什么

- 新增：文档总索引、MVP1 整理版 PRD、AI Prompt/坏例台账、可追溯性入口、变更总台账和后续工作模板。
- 更新：根 README、工作记录索引、原始计划状态、作品集案例页的迭代说明，以及旧导学/面经的历史状态标记。
- 不做：不修改模型 Prompt、Tool、状态机、数据库、部署、MVP1 实验数据、fixture、真实运行记录或发布结论；不删除旧文档。

## 3. 审计发现与决定

| 发现 | 决定 |
| --- | --- |
| 现有工作记录覆盖 Stage 1–25，但缺少统一入口 | 新建 `docs/README.md` 和 `docs/traceability/`，按“产品、发布、AI、实验、部署、后续”导航 |
| `PLAN.md` 含有已暂停或未实现的历史计划项 | 在计划顶部标注历史规划状态；当前能力以 MVP1 PRD/发布决定为准 |
| 没有集中 PRD | 新建 `docs/product/PRD-MVP1.md`，只整理已冻结范围与验收边界 |
| 真实运行只有 `resolution-v1`、`vision-evidence-v1`，没有可比较 V2/V3 | 新建 Prompt 台账，保留缺口；不制造三版本实验故事 |
| 修复散落于工作记录，难以按坏例查找 | 新建坏例台账，记录问题、修复层、验证和未解决项 |
| 两套导学/面经同名材料版本不同 | 保留旧材料，在文件顶部标为历史快照；当前版本使用 `*-CarePilot.md` |

## 4. 验证

- 完成 Markdown 文档清单、阶段记录、可见 Git 历史和 Prompt/运行代码路径审计。
- 新增文档中的关键引用均指向已有工作记录、MVP1 发布材料、运行配置或代码入口。
- 本轮只改文档；无需重新运行模型、数据库迁移或公网部署。提交前执行 Markdown 链接检查与 `git diff --check`。

## 5. 结论、边界与下一步

本轮将“当前产品规范”“冻结发布事实”“历史计划/研究材料”“Prompt/坏例”“变更证据”明确拆分。它能提高已存在事实的可检索性，但不能凭空恢复可见 Git 历史之前缺失的逐文件提交；该缺口已在变更总台账中公开记录。

之后所有实质功能、Prompt、数据或实验改变进入 MVP2；文档治理改变也必须遵循本记录新增的模板和追溯规则。
