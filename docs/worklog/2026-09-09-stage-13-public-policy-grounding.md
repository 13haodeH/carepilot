# 阶段十三工作记录：公开政策 grounding 与前端评审包

- 记录日期：2026-09-09
- 对应计划：为模拟售后 Agent 增加可审计的公开政策参考；保留订单、物流、退款等业务数据的模拟边界
- 交付阶段：**本地 API / 前端技术验证完成；Supabase 需先执行 005 迁移后才可写入远程开发库**

## 1. 决策与边界

不开放前端任意抓取 URL。公开来源是代码内受控清单，避免 SSRF、网页结构漂移和未经审核的政策直接生效。当前 v0.1 清单含国家市场监督管理总局的《网络购买商品七日无理由退货暂行办法》、京东自营商品售后服务总则和京东手机/数码类细则。

来源只为 Policy retrieval 提供参考。订单、物流、退款、支付、库存、客户字段和所有实验任务继续是模拟或脱敏数据；高风险售后权益动作继续要求人工确认。

## 2. 实现

- `data/005_public_policy_grounding.sql` 增加来源 URL、发布方、版本、发布时间、最近校验时间与 checksum 字段，新增不可变 `policy_source_snapshots` 与 `policy_grounding_chunks`。
- `evals/fixtures/public-policy-grounding-v0.1.json` 保存受控来源清单、短摘录和检索片段；导入时以规范化公开摘录计算 SHA-256。
- Policy Admin 改为多来源工作台：选择来源、导入公开快照、查看版本/时间/checksum、运行完整性与片段回归、人工发布、回滚和已发布来源检索均由前端按钮完成。
- Evaluation 增加“下载项目评审包”按钮。后端生成脱敏 JSON，汇总当前数据边界、政策快照状态、离线评测、Manual vs Agent 描述性结果及已知限制；其中不含凭据或真实业务数据。

## 3. 验证

- API 自动化测试：13 / 13 通过，覆盖公开快照导入、checksum/片段回归失败阻断、人工发布、已发布来源检索与评审包模拟数据边界。
- Web build：`/`、`/config`、`/evaluation`、`/experiment` 与 `/policy` 均成功构建。

## 4. 未完成与下一步

1. 项目负责人先在 Supabase SQL Editor 执行 `data/005_public_policy_grounding.sql`；现有 001–004 已执行的前提下，该脚本不会删除已有记录。
2. 远程 API 目前仍是独立 FastAPI 服务；已发布的静态 Site 不能把 `127.0.0.1:8000` 当作生产后端。要实现“只在已发布页面操作”，下一阶段必须部署受鉴权的 HTTPS API 或将受控服务端能力迁移至同源 Worker，并在服务端配置数据库连接，不能把数据库连接串或 service key 放入前端。
3. 当前公开来源是受控初始包，并非任意 URL 的实时爬取。后续版本更新需在导入前重新核验来源和适用性；任何新增来源仍应先进入 Candidate 和人工发布门禁。
