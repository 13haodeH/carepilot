# 阶段十七工作记录：真实视觉冻结集 v0.2

## 目标

将项目负责人提供的图片从文件链路测试素材升级为真实视觉模型评测输入，覆盖明显破损、明显缺件、包装破损状态不确定、模糊遮挡证据不足、与投诉内容不一致五类情况。

## 实现

- 保留 `evidence-v0.1.json` 和抽象图片目录，仅供 fixture/mock 自动化测试使用；真实图片不会进入 `FIXTURE_ANNOTATION` 分支。
- 新增 `real-vision-eval-v0.2.json`：20 张 JPEG 均记录稳定 ID、相对路径、SHA-256、字节数、尺寸、目录标签对应的冻结预期与人工复核预期。
- 新增生成脚本 `scripts/build_evidence_v02_manifest.py`。它只读取已提供的图片并生成 manifest；运行时会重新校验路径、文件大小和 SHA-256，文件变动会使评测拒绝运行。
- 新增 `real-agent-eval-v0.2.json`：9 个真实模型评测工单，其中 5 个接入 v0.2 图片，覆盖五类视觉样本和高风险人工审批情形。
- 真实视觉模型现获得“用户诉求 + 订单商品”上下文，仅用于评估图片是否与诉求一致；仍禁止模型据此决定退款、换货、补偿或资格。
- 真实评测增加“图片 Evidence 命中率”和“图片人工复核判断准确率”；坏例会记录相应字段。管理后台同步展示图片 Evidence 指标，并修正高风险接管指标读取错误。

## 技术验证

- 共发现 20 张 JPEG：明显破损 5、明显缺件 4、包装状态不确定 5、模糊遮挡 3、与投诉不一致 3。
- 技术检查显示这 20 张文件无 EXIF，均小于单图 8 MB 上传上限；图片内容是否不含个人信息以项目负责人确认范围为准。
- API 单元测试 20 项通过，包含 v0.2 文件哈希、五类覆盖、评测引用关系与视觉上下文传递。
- Web 生产构建通过。

## 边界与下一步

- 文件夹标签是冻结评测的人工期望，不会喂给真实视觉模型，也不构成模型输出或业务结论。
- 本阶段未调用模型，因此未产生新的模型费用，也没有生成业务工单或人工审批动作。
- 运行真实评测会按 9 个冻结工单发起多次 DeepSeek 文本/视觉调用并写入 `REAL_AGENT_RUN`。应先单独授权，再根据图片 Evidence 命中、高风险接管和失败类型复盘，而不能把结果预设为通过。
