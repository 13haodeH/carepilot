# 阶段十工作记录：Manual vs Agent 实验运行页与自动记录格式

- 记录日期：2026-09-09
- 对应计划：`PLAN.md` 的 5 人 Manual vs Agent 交叉平衡实验执行界面
- 交付阶段：**本地匿名运行与导出格式技术验证**；未招募参与者、未收集真人记录、未产生实验结论

## 1. 目标与决策

将阶段九的固定匿名分配变成可直接执行的浏览器内任务运行页，而不把实验观察记录写入 Supabase。这个边界使得实验数据仍是研究者持有的脱敏本地文件，也避免需要收集参与者身份或给远端服务额外权限。

同时把“单题易用性”与正式 SUS 区分开：每条任务记录 1–7 易用度；每位参与者完成四条任务后填写一次 SUS-10 原始答案。二者不能互相代替或混合计分。

## 2. 实现

- 新增前端路由 `/experiment`，仅使用 `evals/fixtures/manual-agent-*.json` 的自构造场景、匿名槽位和固定分配。
- 页面从 `P01`–`P05` 选择槽位，依次呈现 4 条已分配任务；开始、完成或停止会写入浏览器 `localStorage`。
- 单任务记录包含条件、Round、时间戳、时长、实际点击步骤数、目标与实际状态、正确性、高风险人工审核是否被观察到、Proposal 修改、接管、1–7 易用度和脱敏备注。
- Agent-assisted 条件只展示固定模拟摘要；参与者必须自行选择最终状态。高风险任务在页面明确要求 `proposal_review` 与人工审核，不会执行退款、换货、退货、补偿或库存操作。
- 4 条任务后显示标准 SUS-10，并另存为参与者级原始答案；导出为任务 CSV 与 SUS CSV 两个文件。清空本机记录必须经确认，且不会影响已下载文件。
- 在 `/evaluation` 增加“进入匿名实验运行台”入口。
