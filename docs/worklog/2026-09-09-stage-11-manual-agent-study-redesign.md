# 阶段十一工作记录：Manual vs Agent 重新设计与 v0.2 执行规则

- 记录日期：2026-09-09
- 对应计划：5 人 Manual vs Agent 模拟可用性实验的重新执行
- 交付阶段：**v0.2 本地运行规则与导出格式技术验证**；尚未招募、未收集 v0.2 真人记录、未产生实验结论

## 1. 问题与决策

v0.1 页面把 fixture 中的预设 `participant_steps` 当作普通任务的完成门槛。这会让每个已完成任务的步骤数趋于固定，与“记录实际工作路径、比较 Manual 与 Agent-assisted 信息操作”的目标矛盾，也容易让参与者误解为需要把所有按钮逐项勾选。

v0.2 保留既有自构造任务和交叉平衡分配，但将预设步骤改为可选的模拟工具入口：点击才表示实际使用并显示相应模拟信息。普通任务只要求最终状态与 1–7 易用性评分；HIGH RISK 任务唯一的硬性门槛是先打开人工审核 Proposal，再选择人工审核。

## 2. 实现

- 实验页新增开始前统一规则、勾选确认、侧栏“如何作答”、三个最终状态含义和 SUS-10 作答说明。
- 移除页面中暴露给参与者的冻结 `target_outcome`，提交后也不反馈对错。
- 使每个工具按钮在首次点击时显示自构造模拟信息，并仅记录参与者实际使用的工具；普通任务不再要求点完全部按钮。
- 新增场景化模拟事实、政策依据与 Agent 摘要。Agent 摘要是可选择查看的建议，不会替参与者提交最终状态。
- 把浏览器存储、CSV 名称和 schema 升级到 v0.2：`information_actions` 与 `information_action_count` 取代会被预设清单污染的步骤数。旧 v0.1 记录不会被读取或混合。
- 新增 `evals/manual-agent-study-v0.2.md` 与 `evals/manual-agent-participant-kit-v0.2.md` 作为重新测试时唯一使用的协议和观察者说明。
