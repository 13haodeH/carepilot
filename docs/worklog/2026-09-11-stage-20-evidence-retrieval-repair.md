# 阶段二十工作记录：检索归一化与订单级 Evidence 复核

## 问题归因

- `HRA-002` 的订单和物流字段完整，`policy.search` 命中过质量政策；图片实际为玩具包装，与耳机订单不一致，因此 `NEED_INFO` 属于订单—图片上下文不匹配，不是库存字段或 Resolution Prompt 过度保守。
- `HRA-003` 的订单和物流字段完整，但图片为破碎玻璃瓶，与耳机订单不一致；三次 `policy.search` 均调用成功但零命中。原因是当时检索只做字面关键词匹配，政策内容存在但 Query 未命中关键词。
- v0.2.1 的图片复核 25% 不可解释为纯视觉准确率：若干图片与订单商品本身不匹配，而旧标签却标为“无需复核”。旧的“明显缺件”匹配还会读取 `review_reason`，可能把诉求文字误计为图片事实。

## 本次最小实现

- 新增 `normalize_policy_query`：仅扩展破损、缺件、换货、签收等有限售后同义词到已发布政策的现有关键词；不引入 reranker、向量库或新政策内容。
- `policy.search` 现在以订单 Tool 提供的规范品类为准，并在真实 Tool output 保存模型传入品类、实际品类和实际检索 Query，便于区分模型调用与检索结果。
- Evidence 保留 `model_needs_human_review` 作为视觉模型原始判断；`needs_human_review` 改为“模型判断 OR 确定性门禁”。门禁仅读取结构化字段：图片质量、订单/诉求匹配、视觉置信度、缺件/破损诉求所需可见字段。
- 新增 `review_gate_reasons_json`，保留门禁触发原因；视觉模型的原始 `review_reason` 不被覆盖。
- 修复视觉信号评测，不再从 `review_reason` 读取“破损”“缺”等视觉结论。

## 新冻结评测边界

- 保留 `real-agent-eval-v0.2`、`real-agent-eval-v0.2.1`、原 20 张图片和 SHA-256 不变。
- 新建 `real-agent-eval-v0.2.2`，引用保留 v0.2.1 的 12 条样本，追加 3 条订单—图片配对的高风险验收样本。评测专用订单不会进入 Consumer 订单列表。
- 新指标分开记录：配对图片观察、视觉模型原始复核、订单级证据充分性、最终复核门禁。旧图片指标以 `legacy_*` 字段保留，不再在页面上作为订单级 Evidence 结论展示。
