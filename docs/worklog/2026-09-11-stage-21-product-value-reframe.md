# 阶段二十一工作记录：客服提效产品价值重构与实验设计

- 记录日期：2026-09-11
- 交付阶段：**产品策略与评测协议冻结；未改业务代码、未执行新实验、未产生新业务指标**

## 1. 问题

阶段十六至二十补齐了真实 Vision、Tool Calling、政策检索、高风险人审和坏例修复。它们证明了 Agent 链路可审计，但连续以技术评测为主会遮蔽 CarePilot 的原始业务价值：减少客服在订单、物流、政策、凭证和工单之间的重复查询与决策准备。

这也会使 CarePilot 的作品集表达与 Wayly 的“可信决策”过度重叠，弱化其作为 B 端工作流产品的区分度。

## 2. 决策

1. 将 CarePilot 的主叙事重置为“客服 AI 决策准备工作台”。
2. 将安全自动处置覆盖率、人工信息操作、决策前信息完整度、低风险处理/高风险决策准备时间、Proposal 结果置为作品集第一层指标。
3. 将 Vision、Tool、Policy、模型成本和高风险阻断降为质量诊断与安全护栏，不再作为首屏主 KPI。
4. 停止新的模型架构、多 Agent、RAG/Reranker、权限/审计/部署扩展；仅允许为客服提效指标、决策包和实验运行所需的实现，或修复现有业务/安全路径失真。
5. 保留 v0.2 实验和 Stage 20 真实模型结果作为历史、技术证据；不回写、不混合、不将其包装为客服提效结果。
