# CarePilot MVP1 PRD：售后决策准备工作台

- 文档状态：**MVP1 整理版 PRD**，2026-09-12 基于已冻结实现、运行记录和实验报告编写
- 适用版本：`carepilot-mvp1`
- 变更边界：本文不修改 MVP1 功能、Prompt、数据、实验输入或发布结论；后续需求进入 [`docs/mvp-v2/`](../mvp-v2/README.md)

## 1. 背景与问题

电商售后客服处理一张复杂工单时，需要在订单、物流、政策、图片凭证和历史工单之间反复核验。难点不是生成一句回复，而是判断事实是否足够、适用什么政策、是否存在权益风险，以及现在应该由系统推进还是由客服决定。

MVP1 的产品判断是：AI 适合承担信息理解、受限查询、证据归纳和建议生成；高风险权益决定不能交给模型自动执行。

## 2. 用户、价值与成功边界

| 角色 | 当前任务 | CarePilot 提供的价值 |
| --- | --- | --- |
| 消费者 | 提交售后问题、补充材料、查看状态 | 让问题和材料进入可处理工单 |
| 售后客服 | 判断当前工单如何处置 | 在一张决策包中看到已核验事实、缺失项、政策依据、风险和下一步 |
| 管理员 | 管理政策、Agent 配置与评测 | 对版本、运行和坏例保留审计与发布闸门 |

MVP1 成功不等于“AI 自动结案”。它的成功边界是：低风险动作只在受控条件下推进；高风险动作始终保留人工最终决定；每次真实模型运行与关键状态变化可追溯。

## 3. 范围与不做什么

### MVP1 范围

1. 物流异常：查询订单、物流与政策后，受控创建跟进任务、更新工单并通知用户。
2. 破损/缺件：汇总订单、物流、图片可见信息和政策，生成 Proposal 并进入客服确认、修改、不采用或接手。
3. Consumer、Agent Ops、Admin 三端；受控政策发布、Agent 配置与评测入口。
4. 真实模型结构化输出、受限 Tool Calling、真实视觉 Evidence 路径、状态机、权限门禁、审计与匿名实验台。

### 明确不做

- 不接入真实支付、退款、库存、履约或真实客户业务系统。
- 不让模型直接执行退款、退货、换货、补偿或库存变更。
- 不将离线 fixture、真人模拟任务或冻结模型运行写成生产 KPI。
- 不为展示复杂度恢复 Multi-Agent、Redis、Reranker 或语音。

## 4. 核心用户流程与功能需求

```text
消费者提交问题 / 补充凭证
        ↓
模型理解诉求，受限读取订单、物流、政策、凭证和历史
        ↓
决策包：事实 + 缺失项 + 政策引用 + 风险 + Proposal
        ↓
规则引擎：AUTO_EXECUTE / REQUIRE_HUMAN / BLOCK
        ↓
低风险受控推进                    高风险客服确认、修改、拒绝或接手
```

| ID | 需求 | 验收与边界 |
| --- | --- | --- |
| PRD-01 | Ops 以当前工单为中心展示用户诉求、订单、物流、政策、凭证、风险、建议和处理记录 | Tool trace、模型成本等运行细节下沉为审计信息，不能取代决策包主视图 |
| PRD-02 | 模型在 Resolution 前调用订单、物流和政策查询；有图片时读取凭证 | 工具必须走服务端 allowlist；缺少必需 Tool 或结构化输出失败即记录失败，不静默使用 fixture |
| PRD-03 | 低风险物流场景只在订单、政策、权限满足时创建任务/通知并推进状态 | 每个 Tool、状态变化与幂等约束留存审计；受控演示 Tool 不等于真实业务系统 |
| PRD-04 | 高风险场景生成 Proposal 而非执行权益动作 | Proposal 必须进入 `WAITING_REVIEW`；客服可采纳、修改、不采用或接手 |
| PRD-05 | 图片只描述可见事实，并在模糊、无关、低置信度或证据不足时要求人工复核 | 视觉判断不裁决退款资格；最终 `needs_human_review` 同时考虑模型与确定性门禁 |
| PRD-06 | 政策先形成 Candidate，经过回归和人工发布才成为 Active | 回答只能引用 `policy.search` 返回的已发布片段；公开政策 grounding 不构成法律结论 |
| PRD-07 | Agent Config 通过 Draft → Sandbox → 人工 Activate / Rollback 管理 | Prompt、模型、Tool 白名单和风险边界不可直接覆盖 Active |
| PRD-08 | 公开实验台为匿名参与者分配 3 道人工检索题与 3 道决策包题 | 记录仅用于自构造模拟任务的过程观察；同一匿名参与者同一题不重复计入 |

## 5. AI 能力选型与人机分工

| 层 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| 模型 | 结构化理解、Tool 选择、政策/凭证归纳、中文建议与 Proposal | 最终业务权限、政策发布、权益写操作 |
| Tool | 返回受控订单、物流、政策、凭证与历史上下文 | 绕过订单归属、角色或白名单 |
| 规则 | 状态机、风险、权限、幂等、Evidence 门禁 | 伪造模型理解或政策引用 |
| 人工 | 高风险决策、修改/拒绝建议、接手异常工单 | 被系统强制接受模型建议 |

当前实际 Prompt、运行版本和已知台账见 [`../ai/PROMPT-REGISTER.md`](../ai/PROMPT-REGISTER.md)。模型提示词不是权限控制层；这一点由 `PRD-04` 的后端状态与 Tool 边界保证。

## 6. Badcase 与数据闭环

每个问题遵循同一闭环：冻结输入 → 真实/模拟运行 → 保存模型与规则输出 → 分类失败原因 → 选择最小修复层 → 新建版本验证 → 保留旧运行。坏例不因修复而删除，详见 [`../ai/BADCASE-REGISTER.md`](../ai/BADCASE-REGISTER.md)。

可回流的数据包括：Tool 调用与失败类型、政策引用、Evidence 原始/最终复核、Proposal 采纳/修改/拒绝/接手、匿名实验中的信息查阅与最终选择。它们用于诊断和后续版本假设，不自动构成模型训练数据或生产用户画像。

## 7. 指标与已验证证据

| 指标 | MVP1 结果 / 状态 | 可作的解释 |
| --- | --- | --- |
| 决策前信息完整度 | 决策包 95.7%，人工检索 61.7%；41 位真人、246 道自构造模拟任务 | 决策包能更完整地组织判断前所需信息 |
| 高风险人工确认 | 99 / 99 真人高风险任务进入人工确认 | 没有通过跳过审核换取速度 |
| Proposal 人机协作 | 45 道高风险决策包任务中 46.7% 直接采纳，其余被修改、不采用或接手 | AI 建议可被审阅，不是自动命令 |
| 真实 Agent 技术链路 | `real-agent-eval-v0.2.2`，15 条冻结样本 | 模型、Tool、政策、视觉与人审链路实际运行且可追溯 |
| 处理时长、操作次数、正确率 | 跨批次不稳定 | 不主张真实客服效率、自动处置覆盖率或经营收益 |

完整口径与限制以 [MVP1 真人实验报告](../mvp-v1/01-human-study-report-2026-09-12.md) 为准。
