# CarePilot MVP1：客服决策准备工作台

- 冻结日期：2026-09-12
- 发布类型：个人作品集 / 可运行技术 Demo
- Git 发布标识：`carepilot-mvp1` 标签
- 后续开发入口：[MVP2](../mvp-v2/README.md)

## 一句话定位

CarePilot 面向电商售后客服，将分散的订单、物流、政策、凭证和风险信息组织为一张可审阅的决策包；低风险事项安全推进，高风险权益事项由客服作出最终判断。

## MVP1 已冻结的内容

| 范围 | 冻结结果 |
| --- | --- |
| 产品流程 | 物流异常低风险推进；破损/缺件高风险 Proposal 与人工审批 |
| Agent 能力 | 真实模型结构化理解、受限 Tool Calling、政策引用、真实视觉路径、Proposal 持久化 |
| 安全机制 | 状态机、Permission/Risk Engine、人工审核、审计与幂等约束 |
| 真人实验台 | 匿名分题、3/3 条件平衡、同 pair 避免重复、服务端提交去重、Netlify/Render/Supabase 部署 |
| 真人过程证据 | 41 位完成参与者、246 条自构造模拟售后任务记录 |
| 质量验证 | 24 条后端测试、Web 生产构建、公开 API 健康检查与实验页访问检查 |

## MVP1 的可用结论

- 决策包条件的平均决策前信息完整度为 95.7%，Manual 为 61.7%；它证明系统能将必需事实更完整地组织在判断前。
- 99 道高风险任务均进入人工确认。45 道高风险决策包任务中，46.7% 直接采纳建议，其余被修改、不采用或人工接手，符合“AI 准备、人工决策”的定位。
- 真人任务中的信息操作、用时与正确率跨批次不稳定；不能主张客服处理时间缩短、生产自动处置覆盖率提升或经营收益改善。

## MVP1 不包含的主张

- 不是真实客服生产试点，也不连接真实订单、支付、库存或履约系统。
- 不是“自动退款/自动换货”系统；高风险动作的自动执行次数必须为 0。
- 不将自构造模拟任务中的真人过程数据外推为 SLA、客服成本、满意度、GMV 或留存。
- 不把冻结模型评测、离线 fixture 或历史 v0.2 实验混入本次真人实验结论。
