# CarePilot MVP1 Demo 脚本（3 分 40 秒）

## 演示目标

用两条售后流程说明 CarePilot 的业务价值：不是让 Agent 替客服拍板，而是让客服少拼接信息、更快进入可判断状态，并在高风险场景中保留最终决定权。

## 录制前准备

- 使用非生产、脱敏 Demo 账号与现有 Demo 工单；不展示任何密钥、环境变量、数据库连接串或真实个人资料。
- 浏览器打开 `/consumer`、`/`（Agent Ops）、`/policy`、`/evaluation`；若无会话，先使用已有演示账号登录，不在录屏中输入密码。
- 选择一个物流延迟工单和一个破损/缺件、状态为 `WAITING_REVIEW` 的工单。不要在录屏中触发真实模型重跑或高风险写操作。
- 录制中不展示历史 v0.2 的本地实验页，真人实验只展示最终汇总，不展示单个匿名参与者记录。

## 分镜与口播

| 时间 | 页面与动作 | 口播要点 |
| --- | --- | --- |
| 0:00–0:20 | 封面或 README 的一句话定位 | “售后客服的难题不是生成一句回复，而是在订单、物流、政策和凭证之间来回查，才能判断当前工单怎么处理。” |
| 0:20–0:45 | Consumer `/consumer`：提交一条物流延迟问题 | “用户只需要描述问题和补充凭证。系统先做订单、物流和政策核验；涉及退款、换货、补偿的权益动作不会自动执行。” |
| 0:45–1:35 | Agent Ops `/`：选中物流延迟工单，依次指向用户反馈、订单和物流、AI 处理建议、政策依据、处理记录 | “这里不是聊天记录，而是一张决策包：客服直接看到已经核验的事实、适用规则、系统已完成的动作和现在需要做什么。低风险场景只在订单、政策和权限都满足时，才推进状态和通知。” |
| 1:35–2:35 | Agent Ops `/`：切换至高风险破损/缺件工单，展示图片凭证、Proposal、右侧人工处理按钮 | “高风险场景的目标不是更快自动结案，而是让客服带着证据和政策进入人工判断。客服可以同意、修改、不采用或自己接手；在批准前没有换货、退款或库存执行入口。” |
| 2:35–2:55 | Policy `/policy` 或处理记录中的 citation | “每个建议都保留政策依据和运行记录。模型负责理解、检索和解释；后端状态机与权限规则负责是否允许改变业务状态。” |
| 2:55–3:20 | Evaluation `/evaluation`：先展示 REAL_AGENT_RUN 区域，再切到真人实验结果文档/图表 | “真实模型运行证明 Tool、政策、视觉和人审链路可追溯；真人实验则验证决策准备机制。两类证据分开，不用技术评测冒充业务效果。” |
| 3:20–3:40 | 展示 `docs/mvp-v1/01-human-study-report-2026-09-12.md` 的结论 | “41 位真人完成 246 道模拟售后任务后，决策包条件的决策前信息完整度为 95.7%，Manual 为 61.7%；99 道高风险题都保留人工确认。时间缩短没有稳定证据，所以我不会夸大成效率提升。” |

## 结束句

> CarePilot 的价值不是用 AI 取代客服，而是把客服从信息拼接中解放出来，让低风险流程受控推进，让高风险决定仍由人掌控。

## 录制验收

- [ ] 两条旗舰流程均出现，且高风险流程没有展示“AI 自动换货”。
- [ ] 决策包先于 Tool trace 出现；Trace 只作为可信度附录。
- [ ] 所有数据均标明模拟/冻结/真人过程数据的适用边界。
- [ ] 未出现密码、API Key、数据库地址、真实订单或个人信息。
- [ ] 不使用“提效提升”“线上落地”“自动化率提升”等无证据结论。
