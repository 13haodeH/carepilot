# CarePilot 客服提效实验设计 v1

- 状态：**设计、v1 任务 JSON、服务端匿名自动分题和公开运行器已实现；未招募、未采集数据、未产生结果**
- 研究性质：自构造、脱敏模拟售后任务下的产品可用性与流程效率观察；不是生产客服实验、线上业务试验或因果证明。
- 与 v0.2 的关系：v0.2 是历史探索性实验，保留但不合并；v1 以新的任务、schema、分配和结果文件独立执行。

## 1. 要回答的问题

在相同的模拟售后目标和相同的底层信息源下，CarePilot 的“决策包”是否帮助参与者：

1. 更少进行手动信息检索；
2. 更快进入可作出处置决定的状态；
3. 在作出决定前拿到更完整、可追溯的信息；
4. 在高风险场景中仍遵守人工审核，而不是以跳过安全门槛换取速度；
5. 对高风险 Proposal 进行采纳、修改、不采用或接手时，留下可解释的原因。

本实验**不**比较模型、Prompt、Single Agent 或 Multi-Agent 版本，也不把模型分数作为主要结果。

## 2. 两种工作条件

| 条件 | 参与者看到什么 | 参与者需要做什么 | 计量重点 |
| --- | --- | --- | --- |
| `MANUAL` | 同一 case 的订单、物流、政策、凭证等分散模拟信息入口；没有汇总 | 自行查证、判断并选择最终处置 | 手动信息检索操作、完成时间、结果正确性 |
| `DECISION_PACKAGE` | 与 Manual 完全相同来源的事实，外加已汇总的诉求、事实、缺失项、政策依据、风险和 Proposal | 审阅决策包；只在需要时额外核验，随后确认、修改、不采用或接手 | 额外核验操作、决策准备时间、完整度、Proposal 结果 |

决策包不是“正确答案”：参与者仍须选择最终状态；高风险场景仍须经过人工审核 Proposal。两组都不得访问外部资料、真实订单或真实客户信息。

## 3. 冻结任务集设计

v1 计划创建 12 组难度匹配的 scenario pair，每组各有一个 `MANUAL` 和一个 `DECISION_PACKAGE` 条件任务，共 24 条条件任务。

| 组别 | 对数 | 场景例子 | 业务目的 |
| --- | ---: | --- | --- |
| 低风险物流/通知 | 4 | 运输长期未更新、签收后状态不同步、可直接解释的配送异常 | 评估安全自动推进和减少重复查询 |
| 凭证与补充材料 | 3 | 图片模糊、缺少包装信息、图片与订单不匹配 | 评估是否清晰识别“还缺什么” |
| 高风险权益决策 | 4 | 明显破损、明确缺件、退换货时限边界、需修改 Proposal | 评估决策准备与人审协同 |
| 政策/历史边界 | 1 | 重复售后或政策条件冲突 | 评估信息整合而非盲目自动化 |

每个 pair 必须冻结以下内容：case ID、品类、风险、用户诉求、底层信息源、Manual 信息分布、决策包内容、必需信息字段、目标处置、是否必须人工审核、可计入的安全自动处置资格。冻结后不得改变既有 case 的语义；调整须创建 v1.1 或新版本。

## 4. 参与者与分配

- 目标：8–10 个匿名参与者；最少得到 8 名完整有效参与者后才写描述性汇总。
- 每人完成 6 条任务：`MANUAL` 3 条、`DECISION_PACKAGE` 3 条。
- 每个 pair 的两个条件不得分给同一参与者；每个条件任务至少由 2 名参与者完成。
- 条件顺序交叉平衡；首题不固定为某一条件，减少学习效应。
- 任务开始前只收集匿名槽位，不记录姓名、联系方式、真实工作单位、屏幕录制或任何真实订单信息。

此样本量仅用于作品集中的可用性与描述性比较，不承诺显著性检验或行业外推。

## 5. 时间与终点口径

| 场景 | 开始时点 | 成功终点 | 不可接受的“缩短时间” |
| --- | --- | --- | --- |
| 低风险 | 打开工单任务 | 选择正确低风险处置，并完成可模拟的状态推进/通知确认 | 跳过订单、政策或权限条件直接标记已解决 |
| 需补充材料 | 打开工单任务 | 正确识别缺失信息并选择补充材料 | 忽略证据不足直接推荐权益方案 |
| 高风险 | 打开工单任务 | 查看人工审核 Proposal 后，选择正确审核/修改/接手结果 | 因跳过审核、把权益操作直接执行而缩短时间 |

高风险不以 `RESOLVED` 作为唯一终点。其核心产物是“客服已获得足够依据并完成最终人审判断”。

## 6. 记录 schema 与指标计算

### 6.1 每条任务必须记录

- `study_version`、匿名 `participant_id`、`pair_id`、`task_id`、条件、轮次、风险和品类；
- `started_at`、`completed_at`、`duration_seconds`、完成/停止状态；
- 实际查阅的来源类型与次数：订单、物流、政策、凭证、历史、人工审核；
- 决策包首次展示时已具备与缺失的必需字段；
- 最终处置、是否符合冻结口径、高风险门槛是否被观察到；
- 高风险 Proposal 的采纳/修改/不采用/接手以及脱敏原因；
- 单题易用性和不含个人信息的观察备注。

v1 可复用 v0.2 的本地存储、停止记录和 SUS-10 原则，但必须使用新的 schema/version/key，不能修改或读取 v0.2 数据。

### 6.2 主要计算公式

| 指标 | 计算 |
| --- | --- |
| 手动信息检索 | `MANUAL` 中参与者主动打开的来源数；按 pair、条件计算中位数与分布 |
| 决策包额外核验 | `DECISION_PACKAGE` 中参与者在阅读包后主动打开的来源数；不能误称为与 Manual 完全同义的点击量 |
| 信息操作变化 | 同一 pair 的两条件中位数差及变化率；同时披露两组界面定义 |
| 决策前信息完整度 | 决策包首次展示时的已具备必需字段数 / 该 case 必需字段数；Manual 在参与者提交时按其实际查阅信息计算 |
| 低风险处理时间 | 正确低风险处置的 `completed_at - started_at`；单独报告 |
| 高风险决策准备时间 | 正确人审/修改/接手的 `completed_at - started_at`；单独报告 |
| Proposal 结果 | 高风险 `DECISION_PACKAGE` 任务的采纳、修改、不采用、接手计数与比例 |

### 6.3 预先声明的判断标准

- 原计划的“人工信息操作中位数下降至少 30%、处理时间中位数下降至少 20%”保留为**待验证目标**，不是既有结论。
- 只有在任务正确性不下降、所有高风险门槛都被遵守、且条件定义透明时，才讨论上述目标是否达到。
- 出现 STOPPED、错误处置、跳过人审或数据缺失的记录必须保留并单独报告，不能为方便比较而删除。

## 7. 执行前质量门禁

1. 两名内部试运行者逐条检查 12 个 pair：两条件使用同一底层事实，难度差异不来自任务文本。
2. 每个 case 都能被独立判断为低风险、需补充材料或高风险人工审核；冻结目标不向参与者展示。
3. `DECISION_PACKAGE` 只提前组织已有事实，不增加 Manual 不能获得的业务信息。
4. 高风险任务中不存在退款、换货、退货、补偿或库存的真实执行能力。
5. 导出文件不含真实客户、订单、图片、姓名或联系方式；观察备注限制为脱敏交互问题。

## 8. 结果输出与边界

执行完成后，新建 `evals/customer-efficiency-results-v1.md`，至少包含：样本完整性、任务/条件平衡、各指标的原始分母、描述性结果、失败/接手记录、参与者反馈、坏例和限制。

允许的结论形式：

> 在 N 名匿名参与者、M 条自构造模拟任务中，决策包条件对应的手动信息检索/决策准备时间为……；高风险人工审核门槛为……。结果仅描述该模拟任务集。

禁止的结论形式：真实客服效率提升、企业 SLA 改善、GMV/满意度/留存增长、模型已经适用于所有售后工单。
