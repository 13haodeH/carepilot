# CarePilot（售后智策）

> 先把一张售后工单查清楚，再让客服带着依据作决定。

CarePilot 是一个面向电商售后客服的 AI 决策准备工作台。它不试图替客服“自动拍板”，而是把分散在订单、物流、政策和凭证里的信息整理成一张可审阅的决策包，帮助客服判断**这张工单现在该怎么处理**。

## 它解决什么问题

处理一张复杂售后工单时，客服通常需要来回查看订单、物流、政策、图片和历史记录。真正拖慢处理的往往不是写回复，而是信息零散、证据不全，以及高风险权益不能由系统直接决定。

CarePilot 将流程收敛为：

```text
用户问题 → 查询订单、物流与政策 → 汇总证据与缺失项 → 给出下一步建议
                                                     ↓
                              低风险：受控推进    高风险：客服确认、修改、拒绝或接手
```

一张“决策包”会明确展示：已核验的事实、适用政策、可见凭证、风险等级、缺失信息，以及建议的下一步。客服无需从一堆系统记录中自行拼接这些信息。

## AI 做什么，人做什么

| 角色 | 负责内容 |
| --- | --- |
| AI | 理解售后诉求、调用受限的查询工具、整理政策与凭证、生成带依据的处理建议 |
| 业务规则 | 校验订单绑定、状态变化、风险、权限与重复操作，决定动作是否允许执行 |
| 客服 | 对高风险建议作最终判断：采纳、修改、不采用或接手 |

物流进度查询、补充材料请求、工单创建与状态通知等低风险动作，只会在规则满足时受控推进。退款、退货、换货、补偿和库存变更等权益动作**不会由 AI 直接执行**。

## MVP1 已包含什么

MVP1 是已冻结的**个人作品集与技术 Demo**，不是生产售后系统。

- 两条完整流程：物流异常的低风险受控推进；破损/缺件的高风险人工协作。
- 可追溯的真实 Agent 运行：模型调用、Tool Calling、政策引用、图片凭证路径、建议、状态变化与审计记录均被保存。
- 公开匿名实验台：参与者在“人工检索”和“查看决策包”两种条件下完成模拟售后任务。
- 前后端分离部署：实验页不含数据库连接串、Supabase service key 或模型密钥；服务端密钥仅保存在受控服务端环境中。

## 已验证什么，尚未声称什么

41 位真人参与者完成了 246 道自构造模拟售后任务。决策包条件的平均决策前信息完整度为 **95.7%**，人工检索条件为 **61.7%**；99 道高风险任务均进入人工确认。

这说明 MVP1 能更完整地准备决策信息，并保留人工对高风险建议的最终控制权。任务用时、信息操作和正确率在不同批次中不稳定，因此项目**不声称**已提升真实客服处理效率、自动处置覆盖率或经营结果。
